# 백야 달리기 — 좌우 다리 교대 수정

밝은 다리는 오른발, 어두운 다리는 왼발로 고정했다. 첫 착지(아틀라스88번)는 오른발 전방, 반 주기 뒤(104번)는 왼발 전방이다. 기존의 같은 밝은 다리가 앞에 반복되는 자세를 새 다리 PNG로 교체했다.

| 항목 | 이전 main | 변경 |
|---|---|---|
| 실제 PNG 자세 | 32 | 신규 다리32자세 |
| 아틀라스 | 512×1440 / 64×96셀 | 동일 |
| 런타임 참조 | 88–119 | 동일 |
| 표시 주기 | 280단위 / 기본1초 | 240단위 / 기본0.8571초 |
| 기본 표시 FPS | 32 | 37.33 |
| 원본 상체·검·머리카락·망토 | 기존 픽셀 | 보존 |
| 이동속도·공격 판정·대미지·쿨타임 | 기존 | 유지 |

## 제작과 보존

최초 두 생성본은 밝은 다리의 반복이 남아 채택하지 않았다. 최종 생성은 색상 관절 가이드를 기준으로 했다. 노랑 가이드는 밝은 오른다리, 초록 가이드는 어두운 왼다리이며 두 궤적은 반 주기 차이다. 가이드는 제작 위치 지시이며 최종 그림은 이미지 생성으로 새로 그린 판금 다리다.

- `run_alternating_source.png`: 최종 생성본에서 일정한 그리드로 축소·이진 알파 처리한 다리 소스. RGB가 남은 완전 투명 픽셀과 쓰지 않는 상체는 제거했다. 원본 생성 이미지 전체를 게임에서 사용하지 않는다.
- `run_upper_reference.png`: 변경 전 main의 원본32장. 상체와 검 픽셀 보존에 사용한다.
- `run_joint_guide.json`: 제작에 사용한 목표 관절 위치. 원본/최종 PNG에서 자동 검출한 실제 관절 좌표가 아니다.
- `pack_white_night_run.py`: 원본 y66미만과 원본 검을 보존하고 다리만 합성한다. 생성 그리드 밖으로 나온 발끝을 이웃 셀 여백에서 회수하고, 최초 버전의0.84 가로 배율은 접힌 정강이를 압축하므로 제거했다. 현재는 네이티브 좌표를1:1로 사용한다. 프레임별 크기 조절이나 재중앙 정렬은 하지 않는다. 이는 생성 그림의 패킹이며 절차적 다리 재작화/포즈 보간/프레임 복제가 아니다.

## 확인한 범위

- 신규32자세의 RGBA 해시가 모두 다르고,32자세 모두 기존 PNG와 달라졌다.
- 달리기 외0–87 구간, 원본 상체와 보호된 검 픽셀이 그대로인지 검사했다.
- 다리/발이 셀 좌우·하단 경계에 닿아 잘리지 않는지 검사했다.
- 32장 전체의 발목 가이드 투영과 실제 다리 그림을 순서대로 대조했다. 겹쳐 보이지 않는 구간(왼발4·5번, 오른발20·21번)은 검토용 점을 생략했다. 표식은 약±2px의 근사치이며 관절 검출의 정답 데이터가 아니다.
- 88번은 밝은 오른발 전방,104번은 어두운 왼발 전방이다. 발목 좌표는 아래 후속 검토 파일에서 갱신한다. 가려진 구간까지 휘도로 자동 분류했다고 주장하지 않는다.
- 마지막→첫 장을 포함한 픽셀 차이와 발목 경로를 확인했다. 단순 차이 수치는 자연스러움 점수로 쓰지 않는다.
- 이전280단위 주기 대신 새 PNG 접지 구간의 발끝 이동량에 맞춘240단위 표시 주기를 사용한다. **37.33FPS는16–32 기본 가이드의 예외**이며 발 접촉 거리와 맞추기 위한 설정이다. 게임플레이 이동속도는 바꾸지 않는다.
- 플레이어로60Hz 수정 전후·깨끗한 버전·색상 점 버전 MP4를 만들었다. 생성과 실시간 시청은 구분한다. 실제 SDL 합성, 기기 자연스러움, 지형/전투 전환은 미검증이다.

기존 사용자 테스트 모음·전체 게임 빌드·GitHub Actions는 실행하지 않았다.

## 재현

```sh
python3 Tools/pack_white_night_run.py
python3 Tools/review_white_night_run.py
```

Pillow·NumPy·FFmpeg가 필요하다. PNG 패킹과 오프라인 재생 자료만 만들고 게임이나 사용자 테스트를 실행하지 않는다.

## 최종 이미지 생성 지시

기본 이미지 생성 도구로 편집했다. 입력1은32셀 관절 가이드, 입력2는 기존 원본 캐릭터다. 핵심 최종 지시: 입력1의8×4 셀과 무릎·발목 위치를 유지하고, 노랑 가이드는 밝은 은색 오른다리, 초록 가이드는 어두운 보라회색 왼다리로 대체한다. 화면 앞뒤 위치에 따라 밝기를 바꾸지 않는다. 첫 행은 오른발 착지, 셋째 행은 왼발 착지이며 상체·투구·머리카락·망토·검은 유지한다. 기존의 가는 분절 판금과 픽셀 부츠를 따르고, 색상 가이드·점·광채·텍스트는 최종 그림에 남기지 않는다.

## 접힘 길이 후속 수정

접힐 때 다리가 짧아 보인다는 사용자 피드백을 반영했다. 기존 패킹의 가로0.84 축소를 제거하고 허벅지·정강이 각각15px인 관절 가이드를 사용해 다리를 다시 제작했다. 뒤꿈치 최대 들림도15→9px로 낮추고, 발이 앞으로 회수될 때는 더 낮게 내려와 정강이가 골반/검 아래로 숨어 짧은 덩어리처럼 보이는 것을 줄였다. 이는 가이드 목표 길이이며 모든 실제 PNG 관절을 자동 검출해 정확히15px임을 증명한 것은 아니다.

펼친 다리를 가진 프레임에도 반대쪽 다리는 접혀 있으므로, 처음 계획했던8프레임 통째 보존 대신 하체32장을 함께 연결했다. 상체·검·머리카락·망토와 비달리기0–87은 계속 보존한다. 이번 후속 수정은 PNG와 패킹·검토 자료만 바꾸며, 직전240단위 주기/37.33FPS와 이동속도는 그대로다.

- `run_previous_revision.png`: 이 후속 수정 직전32장으로, 전후 비교 영상의 실제 기준이다.
- `run_previous_review.json`: 직전 검토 기록.
- `review/folding_before_after.png`: 접힘이 큰92/96/108/112번의 직전/후속 그림 비교.
- 현재 `white_run_before_after.mp4`는 양쪽 모두 같은240단위 주기를 사용한다. 이전 main의 같은 발 반복과 비교하는 영상에서, 직전 버전의 접힘과 비교하는 영상으로 바뀌었다.
- 색상 표식은 위치 가이드를 실제 그림과 대조한 근사치다.2px 이내에 보이는 픽셀이 없는 점과 가려지는 점은 생략한다. 무릎/발목이 모두 보이는 기기 재생의 자연스러움은 사용자 확인이 남아 있다.

최종 후속 생성 지시:32장 관절 가이드의 엉덩이·무릎·발목 위치와 밝은 오른다리/어두운 왼다리 정체성을 유지한다. 접힐 때도 허벅지와 정강이를 각각 약15네이티브 픽셀의 완전한 분절 판금으로 보여주고, 정강이를 짧은 돌기나 골반에 붙은 발로 축약하지 않는다. 무릎과 두 분절이 구분되게 하며, 가이드보다 발을 높이 들거나 더 심하게 접지 않는다. 상체와 검을 유지하고64×96셀/8×4그리드를 보존한다.
