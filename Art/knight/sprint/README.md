# 일반 기사 달리기 —24장 /0.7초

백야에서 확인한 접힌 다리의 읽힘 문제를 일반 기사에도 반영했다. 기존 기사에는 편집 가능한 픽셀 제작 코드가 있으므로 그 제작 코드를 수정해 실제24개의 새 PNG 자세를 구웠다. 런타임 숫자만 바꾸거나 기존 프레임을 복제한 작업이 아니다.

| 항목 | 이전 | 변경 |
|---|---|---|
| 달리기 PNG 원본 | 54자세 중24개 선택 | 새24자세,24개 모두 표시 |
| 기본 주기 / 표시 FPS | 0.7초 /34.29 | 유지 |
| 실제 재생 거리 | 196월드 단위 | 유지 |
| PNG 제작 발 궤적 기준 | 120단위 | 196단위로 동기화 |
| 허벅지·정강이 제작 길이 | 13.25px | 각각14px, 모든24자세에서 일정 |
| 뒤꿈치 들림 | 최대13px | 최대7px, 앞으로 회수할 때 더 낮춤 |

| 달리기 외 영역 | 프레임0–431 | 디코딩한 RGBA가 모두 동일 |

## 원인과 수정

기존 코드는 발이120월드 단위/주기의 속도로 뒤로 물러나지만 게임은196단위/주기로 캐릭터를 옮겼다. 따라서 기존 접지48% 구간에서 이론상36.48월드 단위가 앞으로 미끄러진다. 새 접지 궤적은196단위/주기에 맞췄다. 이는 연속 제작 좌표의 계산이며, 실제 픽셀과60Hz 표시에는 반올림/양자화 오차가 남을 수 있다.

접힌 발목은 기존 제작 좌표에서 골반 약5.02px 근처까지 올라와 상체·검에 가려졌다. 새24자세에서는 최소 약11.32px 떨어져 있고 정강이를 덜 접어 읽히게 했다. **이 거리는 골반–발목 거리이지 뼈 길이가 아니다.** 새 허벅지·정강이는 렌더러가 사용하는 두 점 사이 거리로 각각14px이다. 래스터화/다른 파츠의 가림 때문에 화면에서 모든 관절 끝이 항상 보인다는 뜻은 아니다.

밝은 오른다리와 어두운 왼다리는 반 주기 차이를 유지하며, 위치에 따라 밝기를 바꾸지 않는다. 두 다리를 각각 먼저/나중에 그려 기존 전후 레이어도 유지한다. 한쪽 발목이 앞에 있을 때 반대 발목은 뒤쪽 회복 구간에 있다.

## 파일·런타임 매핑

- `Tools/knight_sprint.py`: 일정한 분절 길이와 연속 발 궤적으로 픽셀 판금을 그리는 기존 제작 코드. 모든 프레임에서 동일한 원본 팔레트와 상체/검 레이어를 쓴다. 가로 축소나 프레임별 재중앙 정렬을 하지 않는다.
- `authored_run_24.png`: 실제 새24자세의8×3 검토용 원본.
- 게임 PNG는 기존 `Assets/Resources/Eclipse/knight_motion.png`이며1024×2914,64×94셀,16열/31행을 유지한다.
- `knightSprintFrames`와 `knightSprintPlaybackFrames` 모두24, 시작432. 각 표시 슬롯은 새 PNG의 동일 인덱스 한 장을 참조한다.
- 내부 `motionClips[1]`의16슬롯은 기존 위상 계산/레거시 아틀라스용이다. 해당 슬롯을 화면에 직접 재생하지 않는다. `clips.json`은 레거시16개를 보존하고 `display_*`에 실제 새24장 계약을 별도로 기록한다.
- `run.json`: 실제 제작 좌표와 PNG SHA256. `review.json`: 표시/관절/접지 계산 범위.
- 이전54장 예약 영역과 이전24개 표시본은 각각 `before_run_region.png`, `before_displayed_24.png`로 보존했다.

## 확인 범위

24개 PNG 해시가 모두 다름, 게임 아틀라스와 검토 PNG의 인덱스/그림 일치, 셀 경계 잘림 없음, 기존 팔레트/이진 알파, 상체·검 레이어 보존, 비달리기 영역의 main 대비 픽셀 동일성을 정적으로 확인했다. 원본 제작 관절 기준으로 허벅지·정강이 길이가24장 모두14px임을 확인했다.42개의60Hz 표시 샘플로0.7초를 구성하고24자세가 모두 선택되는 것을 확인했다.

제공된 `eclipse_sprite_tool.py`로 정상 속도 전후·클린·색상 점·0.25배속 MP4를 만든다. 파일명은 **현재 PNG와 검토 스크립트의 해시**로 구분해서 이전 링크와 혼동하지 않도록 했다. 노랑은 오른발, 초록은 왼발이며 점 좌표는 이 PNG를 직접 그린 제작 관절 좌표다. 수동 추정/자동 관절 검출 결과가 아니다.

전체 게임 실행, SDL 합성·실기기 자연스러움·지형/전투 전환 검증은 하지 않았다. MP4 생성과 연속 시청은 구분한다. 기존 사용자 테스트 모음·게임/APK 빌드·GitHub Actions도 실행하지 않았다. 이동속도·공격 판정·대미지·쿨타임·히트박스와 다른 캐릭터/동작은 수정하지 않았다.

## 재현

```sh
python3 Tools/knight_sprint.py --bake-only
python3 Tools/review_knight_sprint.py
```

이 명령은 달리기 PNG와 오프라인 자료만 만들며 게임/테스트를 실행하지 않는다. 전체 모션 재생성용 `bake_knight_motion.py`도 새24자세와 표시 메타데이터를 사용하도록 동기화했다.
